# PCI DSS overview

## Public summary

PCI DSS, the Payment Card Industry Data Security Standard, is published by the PCI Security Standards
Council. According to the Council's standard page, it was developed to encourage and enhance payment card
account data security and to help organisations around the world adopt consistent data security measures.
It sets a baseline of technical and operational requirements designed to protect payment account data.

## Who it applies to

- Any entity that stores, processes, or transmits cardholder data (CHD) or sensitive authentication data (SAD).
- Any entity that could affect the security of the cardholder data environment (CDE).
- In practice this covers every kind of participant in card processing: merchants, processors, acquirers,
  issuers and service providers.

## Who decides whether an organisation complies

The standard page does not set out penalties or a single enforcement body. Compliance requirements are
determined by organisations that manage compliance programmes, such as a payment brand, an acquirer or
another entity.

## Terms used on the standard page

- CHD: cardholder data.
- SAD: sensitive authentication data.
- CDE: cardholder data environment, the systems and processes that handle that data.

## Versions

The Council's resources refer to PCI DSS v4.x, including v4.0. The summary page does not list the individual
requirements, so the standard itself must be consulted for the detailed controls.
